# Large-swarm testbed (not reported in the paper)

Generated LLM agent swarms that perform a vendor-payment approval task, with distributed attacks
planted anywhere on the route to the decider, and an evaluation of graph-only monitoring
allocation policies. It uses the same release schema as the paper's topology testbeds but
larger generated topologies. The paper does not report it; see finding 3 below.

## Environment

- **Topologies** (`topology.py`): three generated families modelled on documented systems.
  Orchestrator–worker with dispatch and collection sub-orchestrators, aggregators and division
  heads. Teams of teams with leads, department heads, a committee and an optional audit team.
  Review pipeline with analysts, function coordinators, reviewers, senior reviewers, approvers
  and an optional compliance desk. 41–66 agents, 106–211 channels, 5–10 hops deep. Assurance
  variants: `line` (audit/QA/compliance report into the line) and `none` (no funnel).
- **Task** (`case.py`, `llm_run.py`): each agent is one Gemma-4-31B call. Function owners read
  their source record and compute their check; cross-checkers from other teams report advisory
  results; relays forward check results to whoever needs them; the decider pays only if all
  five checks pass. Unassigned workers send routine updates about other invoices. Honest noise:
  in about 40% of cases one cross-checker reads a stale record.
- **Attacks**: each attacked case fails two checks. Fragment A makes one pass, fragment B the
  other. A fragment is a compromised worker (false raw facts), a compromised relay (flips a check
  result) or an in-transit channel rewrite (as in MESA). Placements are drawn on the check's
  route to the decider, so corruption can sit anywhere on that route, not anywhere in the graph.
- **Conditions**: clean (2 failing checks), A, B, AB, and pay (a separate case that should pay).

## Dataset (`release_main/`, shared schema)

`allocator_inputs.jsonl` (anonymous graph, k, s), `judge_data/observations.jsonl` (messages with
sender, recipient, round), `evaluation/labels.jsonl` (origin channels, propagated false
channels, corroborating channels, honest-noise channels, realized decision, case pattern).
Split by case cluster, never by condition: conditions of one case share most messages.

- 144 cases × 5 conditions = 720 swarm runs, 2.96 credits.
- Case patterns: 115 distributed (A HOLD, B HOLD, AB PAY), 17 single fragment sufficient
  (mostly teams, whose decider has one input), 12 attack failed.
- Clean holds in 144/144 and pay pays in 143/144. About half of the clean and pay runs contain
  an honest disagreement.
- In AB runs of the pilot, the decider's inputs never held both versions of an attacked check;
  the nearest evidence sits 1–3 hops before the decider.

## Evaluation (115 distributed cases; half or three quarters of channels, 8 per judge call)

Primary metric: exposure (the judge flags a channel carrying the false version of an attacked
check). Secondary: origin attribution (an origin channel is flagged). Strata: liar role ×
evidence geometry, at least 10 fragments each. Full outputs: `out/analysis_proxy_v2.txt`
(structural judge) and `out/analysis_llm_v2.txt`, `out/llm_fpr_v2.txt` (LLM judge, 7.5 credits).
The per-call evaluation files are regenerated by the commands below and are not tracked.

| Policy (k = E/2, s = 8) | Structural judge: mean / worst | LLM judge: mean / worst | LLM false accusations |
|---|---|---|---|
| Path coverage | 43 / 24% | 47 / 44% | 7.1% |
| Random selection, random groups | 48 / 25% | 57 / 35% | 2.7% |
| Random selection, path groups | 58 / 32% | 51 / 28% | 5.5% |
| Last layers (sink-anchored) | 61 / 0% | 25 / 5% | 2.6% |
| Shared-receiver groupings | 32–37 / 0% | 1–12 / 0% | 2–3% |

Findings:

1. No policy is best in every stratum. The deterministic rule with the best structural average
   (watch the last layers) has a stratum it never catches.
2. With the structural judge, a maximin mixture beats the best fixed policy on held-out case
   clusters (34 vs 25%), but a single randomized policy gets most of that gain (31%).
3. With the LLM judge, the mixture does not beat the best fixed policy held out (32 vs 30% at
   E/2, 46 vs 47% at 0.75E). Path coverage is the most robust single policy, partly because it
   accuses more. Random selection with random groups has the best exposure for its false
   accusation rate.
4. The structural judge overrates receiver grouping: the LLM judge rarely decides which of two
   conflicting sibling reports is false.
5. The judge, not the allocation, is now the bottleneck. Origin attribution stays at 7% or
   less in every policy's worst stratum, and at least one false accusation occurs in 44–97% of
   clean runs.

## Reproduce

```bash
PY=.venv/bin/python
./swarm/run_main.sh                                   # generation (needs ADAPTION_API_KEY, see .env.example)
$PY -m swarm.export swarm/out/llm_main swarm/release_main
$PY -m swarm.evaluate swarm/release_main --judge proxy --conditions AB --budgets 0.5:8,0.75:8 --random-seeds 20 --out swarm/out/eval_proxy_v2.json
$PY -m swarm.evaluate swarm/release_main --judge llm --conditions AB,clean,pay --budgets 0.5:8,0.75:8 --out swarm/out/eval_llm_v2.json
$PY -m swarm.analyze2 swarm/out/eval_llm_v2_fragments.json 0.5:8 0.75:8
```

Runs record their spend per call in `out/ledger.jsonl` (the published runs used 10.45 credits).
